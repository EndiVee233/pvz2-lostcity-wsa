# 第十五轮：字符串驻留、计数、回收与名称句柄接入

本轮新增可独立运行的 `InternPool`，恢复驻留文本查找、编号取得与复用、引用计数、归零回收和普通驻留值赋值。名称句柄赋值、规范化和对象解析已能直接调用新驻留池，不再只依赖记录 retain/release 的测试桩。完整游戏的源码构建仍未达到。

- [engine_intern.hpp](../../native_recovered/include/engine_intern.hpp)：接口与明确的宿主移植边界。
- [engine_intern.cpp](../../native_recovered/src/engine_intern.cpp)：驻留条目、链表和字符串索引实现。
- [recovered_rb_tree.hpp](../../native_recovered/include/recovered_rb_tree.hpp)：描述符树与驻留树共用的已恢复树算法。

`011f13a8` 的原始单例创建/复用路径在 ARM 验证中实际执行；恢复类采用显式实例，并使用其初始化结构依据，没有把显式实例当成原游戏全局单例的线程/销毁语义。地址仍沿用 Ghidra 加载偏移 `0x10000`。

## 确认的行为

编号为条目索引加一，0 表示空输入或空字符串。`intern` 取得编号但不增加引用，新条目初始计数为 0；`acquire` 对编号增加引用。重复文本命中已有条目，不分配第二个编号，也不调整链表次序。

引用归零时，原函数先按当前文本删除树节点、减少树计数，再把文本清空并将条目从活动链表移动到空闲尾。取得新文本时优先从空闲尾取条目，因此会复用最后释放的编号。编号不携带对象槽位句柄的代数，不应将两者混同。

普通驻留值赋值严格先释放旧编号，再写入/增加新编号，即使编号相同也不跳过。单引用的同编号赋值会先使条目归零回收、清空文本，之后又把该空闲条目的引用增回 1。这是本轮实际执行原指令确认的边界行为，没有将其改写为更常见的先 retain 后 release。两字名称句柄 `001e9bb4` 则先 retain 两个新引用、再 release 两个旧引用，顺序不同。

计数增减采用 32 位回绕。单独释放一个计数为 0 的有效条目会产生 `0xffffffff`，不会走归零回收。`release_value` 不清除输入驻留值中的编号字段，这一点也保持原样。

## 验证与连接结果

原 ARM 执行 35 个场景、1,240 个操作后完整状态检查点。原始创建、指针表扩容、驻留树插入/删除、计数和回收均直接执行；同时实际执行 460 次原 Android COW 宽字符串赋值，没有把宽字符串赋值函数本身替换成 Python。

控制的底层边界包括成功分配的分配器、libc 内存操作、宽字符长度/比较/复制，以及单线程 ARM kuser 比较交换辅助入口。它们用于运行取证环境，不属于本轮恢复的引擎逻辑，也不证明原 libc、原 COW 字符串 ABI 或多线程行为已恢复。

状态比较包含编号表条目数与容量、每个条目的编号/计数/完整 UTF-32 文本、空闲与活动链表的双向连接，以及字符串树的头节点、根/极值、颜色、父子关系和条目索引。原地址规范化为编号或节点序号，逐个整数比较，不使用状态哈希。另检查调用后的栈与被调用方保存寄存器。

覆盖空/空指针输入、英文大小写、中文、非 BMP 字符、组合字符、前缀文本、内嵌零终止、重复取得、容量增长到 64、不同释放次序、编号复用、32 位计数边界、普通值赋值、同编号赋值，以及八组固定种子的混合操作。

名称句柄场景让原 `001e9bb4`、`011e761c` 和 `001ea034` 直接调用原始驻留池，不再截获驻留服务；C++ 侧同样直接传入新 `InternPool`。确认真实计数能在句柄持有期间维持名称、解析时临时增减引用保持平衡、清空句柄后释放名称，并覆盖两个名称使用同一编号的情况。类型库、名称树和对象槽位在这些场景中仍使用固定初始数据，不构成完整类型注册证据。

为了让驻留树与描述符树共用恢复出的算法，本轮把前驱、后继、左右旋转、插入平衡和删除平衡抽成 `recovered_rb_tree.hpp`。第十四轮 3,995 个完整树状态检查在抽取后重新通过；原有档案、修改标记、句柄、注册表和槽位检查也均通过。

## 移植边界与后续工作

恢复类用 `std::u32string` 表达文本，宿主条目通过稳定的独立对象保存，指针表记录逻辑容量。原 Android COW 缓冲区布局、容量、共享引用及原始文本地址不在 C++ 等价范围内。为避免截断宿主指针，`text_address` 返回编号令牌，由 `text(token)` 读取内容；该令牌不可当成原 ARM 或宿主内存地址解引用。

原始代码对有效编号和索引关系有前提；本轮不覆盖无效/越界编号、缺失索引释放、分配失败、重入和并发。宿主的边界检查和异常不是原游戏错误处理的恢复。普通构建不需要原始 `.so`；取证脚本仍需要读取原库执行指令。

类型名称树/对象名称树的完整写入、类型注册及 RTTI、真实对象类、资源异步载入、完整存档序列化和上层游戏运行时仍未补齐。ProfileStore 仍保留此前的宿主档案后端。新代码尚未接入 APK，本轮没有修改 APK、安装内容或用户存档。
