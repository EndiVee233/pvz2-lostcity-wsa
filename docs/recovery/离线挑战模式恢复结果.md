# 离线挑战模式恢复结果（v10）

日期：2026-10-30。

恢复地图右侧“挑战”中的邪恶入侵、巨人危机、暴走雪人。WSA 中三种普通难度均已离线载入；邪恶入侵出现僵王与传送带，巨人危机可布阵并开始波次，暴走雪人可选卡、开始战斗、暂停并退出。

本轮交付是已有 Android 程序的可重复生成补丁，仍依赖原生游戏库；不代表核心引擎已全部恢复为可编译源码。

## 修复内容

- 挑战的服务器时间请求失败时，读取设备时间，调用原有日期检查、每日次数刷新、奖励随机记录生成与保存函数，再打开原有难度窗口。
- 使用保留的活动配置：当前三种挑战每天各 1 次。沿用原有“仅日期向前才刷新”的比较，同日重新打开与设备日期倒退不会补满次数。
- 奖励随机记录为空时通过原函数生成；已有同日记录继续使用。原程序在胜利流程扣除次数，本轮没有改成进入关卡即扣除。
- 单独跳过挑战子菜单中会禁用另外两个模式的首次引导高亮。玩家引导进度字段、其他菜单引导、传奇难度解锁条件保留。
- 延续多存档、启动弹窗抑制、16 线程纹理解码、四个地图入口移除、原版加速按钮及其本地充值门槛移除。

## 原生定位

以下是 Ghidra 地址，代码文件偏移通常减去 `0x10000`。

| 地址 | 恢复出的作用 |
| --- | --- |
| `0x00a3f200` → `0x00a49254` | 挑战入口、子菜单选择 |
| `0x004213b0` → `0x00f86478` | 请求服务器时间、挑战专用完成回调 |
| `0x00f864a8` | 原错误弹窗体，改为设备时间回退、每日初始化 |
| `0x00758d3c` | 根据日期和活动配置刷新原有次数 |
| `0x00737ed8` / `0x007210c4` | 生成奖励随机记录 / 保存 |
| `0x00420c24` / `0x008529c8` | 打开原有挑战窗口 |
| `0x008553dc` / `0x00854818` | 难度、次数检查与关卡启动 |
| `0x00a4880c` | 子菜单引导状态读取，挑战菜单返回中性状态 |
| `0x00721e88` | 胜利时沿用的原次数扣除函数 |

设备时间回退占用原错误弹窗体的 152 字节；子菜单跳板占用其后 16 字节。代码使用相对寻址，保持栈对齐与调用者保存寄存器；没有新增绝对运行时地址或修改全局联网判断。

| 巨人危机 | 1 | `festival_lv1_easy` |
| 暴走雪人 | 0 | `festival_lv2_easy` |

## 验证结果与边界

162 个 ARM 检查通过：18 个服务器成功/失败、三模式、旧日期/同日/未来日期组合；117 个菜单种类与引导状态组合；27 个原次数扣除检查，覆盖三个模式、0/1/3 次与不同混淆密钥。执行原挑战回调、日期刷新和次数扣除代码，操作系统、配置、事件、存储与 UI 边界受控。它们不等同于完整引擎测试。

WSA 实际安装 `com.popcap.pvz2cthd.reconstruction` 的 v10 runtime-only 验证包，复用已有资源。确认：

- 三个普通难度关卡均已载入，未出现“活动需要联网状态下才能开启”。
- 首次本地刷新后显示各 1 次，保存了 15 条原生奖励随机记录；重启与多次返回后的记录保持一致。
- 暴走雪人正常暂停、确认退出并再次打开难度窗口。
- 两个玩家的 UID 与昵称映射一致，测试前后金币 5880、钻石 18；未支付或消耗测试货币。
- 当前进程日志未发现致命信号、Java 崩溃或链接错误。

**未完成完整胜利后的实际领奖验证；困难、传奇难度也未实机跑完。** 原有奖励与胜利扣次流程保留，次数扣除通过 ARM 检查；不将这些记为完整通关已验证。每日跨日刷新通过受控日期检查验证，没有修改 WSA 系统日期。
