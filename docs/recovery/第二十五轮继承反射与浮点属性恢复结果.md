# 第二十五轮：继承反射与浮点属性

当前工具默认支持第二十九轮的十一类；下述七类历史样例可使用 `--intro-only` 重现，最新结果见 [第二十九轮报告](第二十九轮关卡定义与模块连接恢复结果.md)。

本轮将数据装载范围从一种真实类扩展到七种，新增 `GameObject → PropertySheetBase → LevelModuleProperties → IntroModuleProperties → StandardLevelIntroProperties → DangerRoomLevelIntroProperties` 继承链。源码工厂可创建这些类的数据表示，填充继承字段，并与此前的 GroundEffect 对象形成循环和跨包引用。

**这是数据层恢复，尚不执行游戏方法。** 通用反射模式构建器、事件订阅/游戏回调和 Android 对象 ABI 尚未移植。对真实 Cowboy DangerRoom 明文资源，当前只支持其中 1/5 个声明对象，不能运行完整关卡；这个比例也不是整游戏恢复率。

| 类 | 原工厂 | 本轮数据范围 |

此前的 `EntityComponent_GroundEffect` 继续保留，原有 54 个状态检查全部通过。抽象根类 `RtObject` 仍返回空工厂结果。

字段依据真实注册回调及完成后的原模式检查：`m_thisPtr` 位于原偏移 `0x08`，`ResourceGroupNames` 位于 `0x10`；Standard 的六个字段依次位于 `0x1c`、`0x20`、`0x24`、`0x28`、`0x2c`、`0x30`。宿主对象使用显式字段和逻辑令牌，不把这些 ARM 偏移直接套在 Windows 对象上。

Standard 和 DangerRoom 的默认值经原工厂确认：镜头起止偏移 `78`、`468`，右/左移动时间 `2`、`2.5`，两个旁白编号均为 `-1`。资源列表保留顺序、重复项和空字符串；重新填充可替换或清空列表，缺少字段保留当前值。非数组列表值按原读取路径清空。当前列表元素限定窄字符串，不包含任意类型转字符串。

类链通过显式 `register_level_intro_classes()` 加入当前数据运行时；重复调用不重复登记。类模式由本轮已确认字段显式实现，尚未成为读取任意原反射模式的通用构建器。

## 浮点属性读取

补充 `011f9ae8` 的数值及普通窄十进制文本分支，接口返回 float32 原始位模式。覆盖有符号/无符号 8、16、32、64 位整数，原 float32 位模式、double 转 float32、窄字符串及缓存字符串，以及空偏移/未知标签的回退和精确读取位置。

3,462 个原 ARM/C++ 对照覆盖整数精度边界、舍入中点、极小数、溢出、正负零、无穷和 NaN 的二进制输入。发现并修正宿主默认转换差异：原 ARM 的 double 转 float32 将 NaN 规范化为正 `0x7fc00000`，原 float32 输入则保留其位模式。

十进制文本的外部 `strtod` 使用受控宿主 C 运行库，再执行原 ARM 浮点转换辅助函数。没有据此证明 Android 与宿主全部 libc 行为等价；源码明确拒绝未验证的十六进制/NaN/无穷文本、宽字符浮点解析和 RTID 浮点强制转换。通用数值读取仍未全部恢复，本轮不新增“完整恢复原函数”的数量，已登记语义操作仍为 116 项。

## 原代码与源码的对照范围

34 个连续操作产生 50 个完整数据状态检查点，覆盖：

- 八个类目录项的顺序、父类和所有空值/类组合的派生关系。
- 七种真实工厂的字段默认值、继承属性填充、混合类循环引用和跨包目标后加载。
- 整个驻留池条目、容量、引用、链表和树，以及两个游戏对象库的全部槽位、链表、代数、名称树和描述符树。
- 字符串列表的内容及次序、浮点原始位模式、旁白位模式、对象生存状态及引用解析身份。
- 未知/抽象类空项、跨类重复别名首次登记生效、缺少/错误 objdata、错误版本保留旧对象、清空和重建。

原 ARM 执行真实反射管理器初始化/收尾、七个工厂、完整创建/填充两遍流程、属性分派和引用解析，没有把这些高层路径替换成测试桩。`GameObject::Serialize` 还会触发读后通知：取证按 `_INIT_134` 准备空事件总线并执行真实通知路径，没有游戏订阅者。**宿主数据适配器尚未实现该事件总线或游戏回调，事件总线状态不在本轮比较范围内。** 对应原汇编保存在 `game_object_serialize.asm`。

原/宿主字符串列表只比较逻辑内容，未声称复现 COW 内存身份或分配容量；未初始化填充、虚表地址、全局模式/符号表物理 ABI 不比较。低层分配、C 库、单线程 pthread 和进程退出注册边界继续受控；`pthread_once` 仍实际执行初始化回调。

## 真实资源与独立工具

Cowboy DangerRoom 输出（本地材料） 来自 APK 中已有的 `assets/pvz2tool/features/level_replace_enable/COWBOY_DANGERROOM.RTON` 关卡替换资源，使用此前解密保存的明文，未重新编码或删减输入对象；来源路径及明文摘要写入核对记录。在仅注册本轮类的取证环境中，原 ARM 和源码装载结果一致：第 2 号声明创建 `DangerRoomLevelIntroProperties`，读取空 objdata 后保留上述默认值，其余四个未恢复类保留为空。独立工具返回 `3` 明示部分装载；JSON 的 `success` 是原装载遍历返回值，不表示完整关卡成功。

另有 混合类循环图（本地材料）：完整填充开场对象八个继承字段，连接一个 GroundEffect 对象，形成 `Intro.m_thisPtr → Effect` 和 `Effect.m_effect → Intro`。它是依据真实模式构造的聚焦场景，与真实资源样例分别记录。此前 GroundEffect 循环样例也通过工具回归。

```powershell
# 在 native_recovered 目录执行；此样例两类均支持，返回 0
.\build\rton_load_objects.exe ..\native_analysis\core_round25\intro_reflection\example\mixed-cycle.raw.rton objects.json --intro-only
# 实际关卡仅装载 1/5，写出部分结果并返回 3
.\build\rton_load_objects.exe ..\native_analysis\core_round25\intro_reflection\example\cowboy-dangerroom.raw.rton partial.json --intro-only
```

原生工具由源码构建，运行不加载原引擎。只有重新生成 ARM 参考数据时读取原 `libSrc.so`。资源解密仍来自已有 Python 工作流，原生资源解密尚未恢复。

## 构建与距离目标的进度

完整 `native_recovered/build.ps1` 已通过：17 个 C++ 编译单元、18 个检查程序、3 个工具，使用 C++17 和 `-Wall -Wextra -Werror`。本轮新增 3,512 项，累计 **44,768** 项通过；CMake 已同步但未执行。

新增证据可通过 `scripts/recover_rton_float.py`、`scripts/recover_intro_reflection.py` 生成；独立工具核对用 `scripts/validate_intro_loader.py`。`scripts/record_round25_validation.py` 仅在构建通过后记录证据和产物摘要，不替代构建检查。

原 APK、安装内容和存档未修改。详见 [全源码构建进度](完全从源码编译进度.md)。
