# 第二十四轮：反射工厂、属性填充与引用解析的首个数据闭环

本轮将 `EntityComponent_GroundEffect` 的真实工厂、属性和弱引用规则移植为可独立编译的数据装载路径。原 ARM 取证执行真实反射注册管理器、工厂及两遍加载函数；C++ 能从相同 RTON 创建数据对象、填充 `m_type` 和 `m_effect`，解析前向、循环、跨包和描述符引用。

| 原函数/入口 | 本轮范围 |

| `011f595c` | 沿父类链接判断派生关系；保留空基类的失败结果 |

| `001ea034` 及既有对象库 | 将符号/直接句柄解析到对象身份；继续使用已恢复的别名、描述符和代数检查 |

原流程分两遍：先根据 `objclass` 创建对象并登记别名，再读取每个对象的 `objdata`。因此前向引用和对象间循环不会因先后顺序被误判为空。

重复加载前执行软重置。未知类或抽象类的工厂结果为空，保留结果数组中的空项，并回收占位槽。加载器中的重复别名保留首次登记者，这与此前普通名称绑定接口的覆盖规则不同；新增 `insert_loaded_name`，没有修改普通绑定语义。

缺少字段保留工厂默认值；本类默认枚举为 `ffffffff`、引用为空。缺少或非对象 `objdata` 不填属性，原第二遍返回值也不会汇总每个对象的失败。错误版本在清理原对象之前返回，因此保留原库内容。

相对包名 `.` 使用当前对象库的有效包/名称；指定包名通过注册表名称查找；描述符引用通过三字索引转换；符号引用延迟到解析时按别名查找。源码保留句柄的驻留引用所有权，重置时释放字段持有的符号名称。

## 修复跨模块驻留副作用

原规范化器处理 RTID 时也会临时驻留包名和对象名，即使最后释放，条目数量、容量和空闲链顺序仍可能变化。此前独立文件转换只保证输出字节/偏移，未把这些全局副作用接入宿主池。

本轮给 `normalize_rton` 增加可选共享 `InternPool*`。在同一资源装载运行时中，先传入该池进行规范化，再执行工厂和属性读取，保留临时名称的申请及释放顺序。默认无共享池的独立转换模式继续可用。完整状态对照已覆盖“旧对象仍存活时规范化新引用，再重置并重建对象”的情形。
