当前工具默认支持第二十九轮的十一类和 CurrentLevel 包名；下述十类历史结果可用 `--wave-only` 重现，最新状态见 [第二十九轮报告](第二十九轮关卡定义与模块连接恢复结果.md)。

这仍是数据装载：未执行生成僵尸、调度波次或关卡运行逻辑，外部 `ZombieTypes`、`HeroTypes` 对象库也未完整加载。4/5 不是整游戏恢复率。

## 工厂、字段和嵌套模式

原类型入口 `009c6944` 继承 `LevelModuleProperties`，原工厂 `009c4c70` 分配 `0x60` 字节。真实反射管理器初始化及注册回调执行后，直接字段为：

| 字段 | 原偏移 | 数据规则 |
| --- | --- | --- |
| `m_thisPtr`、`ResourceGroupNames` | `0x08`、`0x10` | 继承的弱引用与字符串列表 |
| `HeroProps` | `0x20` | 默认符号引用 `DefaultHeroLevelProps@HeroTypes` |
| `Waves` | `0x28` | 波次记录列表，默认空 |
| `ZombiePool` | `0x34` | 僵尸池记录列表，默认空 |
| `FlagWaveInterval`、`WaveCount` | `0x40`、`0x44` | int32，默认 -1 |
| `WaveSpendingPointIncrement`、`WaveSpendingPoints` | `0x48`、`0x4c` | int32，默认 -1 |
| `SpawnColStart`、`SpawnColEnd` | `0x50`、`0x54` | int32，默认 -1 |
| `SpawnCount` | `0x58` | 已注册，但原工厂没有初始化；见下文 |
| `IgnoreFlagCarriers`、`IsRiseFromGroundMode` | `0x5c`、`0x5d` | bool，默认 false |

该模式的计算属性列表为空。真实资源中的额外键 `LevelXMLFilename` 不在这些注册字段内；本轮保留原反射读取对它的忽略行为，没有声称恢复 XML 读取或生成波次的游戏方法。

五种值结构从完成后的真实模式和原向量扩容路径核对，字段及偏移保存在 `wave_nested_schemas`：

- **波次记录（原大小 112）**：生成开关、拖拽列、生成列、植物能量数量、波次点数、事件配置、生成时间，以及五份嵌套列表。
- **事件配置（原大小 16）**：Enabled、Count、TimeSpread、Waves；后三者是整数，不能将 TimeSpread 推断为浮点。
- **僵尸生成记录（原大小 56）**：行枚举、植物能量开关、Loot、Level、Type 引用、升起坐标、SunDrop、BesiegeHit、ZombieRate、ZombieScale、TargetValidTime。
- **僵尸池记录（原大小 24）**：Cost、Weight、Overridden、Type 引用。
- **种子池记录（原大小 32）**：Weight、MaxCount、MaxCountIncludesPlanted、Type 引用。

已核对嵌套构造默认值：波次生成时间 2；僵尸生成记录 Level=1、BesiegeHit=1、ZombieScale=1、TargetValidTime=1.5；僵尸池 Cost/Weight=-1；种子池 Weight=1000、MaxCount=0。行枚举使用文本 `1..6` 映射到 `0..5`，`?=6`、`prev=7`，默认 6；数值输入与任意文本强制转换没有因此全部恢复。

读取保留缺少字段时的旧值；重叠列表元素更新原记录，新元素重新取得构造默认值。非对象元素不填字段。嵌套列表当前要求数组，错误类型明确报错；任意畸形嵌套上下文传播仍未恢复。Event 只是配置结构，没有执行游戏事件。

## 保留引用所有权和原始销毁顺序

原工厂先驻留 `DefaultHeroLevelProps`，再驻留 `HeroTypes`，最后由 HeroProps 持有两者。源码按同样顺序构造、赋值和释放临时引用，保留驻留编号及空闲链副作用。

嵌套 Type 引用继续走既有二进制 RTID、包/别名及描述符解析路径。新增所有者在缩容、清空和销毁时显式释放：向量内部按原顺序从前向后；波次记录内按原析构 `009c7710`，依次释放 RemoveFromSeedPool、AddToSeedPool、RemoveFromZombiePool、AddToZombiePool、Zombies。生成器先释放 ZombiePool，再释放 Waves、HeroProps，最后进入继承字段清理。这避免宿主容器的默认析构顺序改变驻留池的空闲链。

原删除析构 `009c7a18` 实际执行；其对应的非删除析构依据为 `009c78b4`。检查包括所有嵌套引用的位模式、最终对象身份、驻留引用计数及整个池/树/链表状态。

## SpawnCount 的未初始化状态

工厂取证发现，虽然 `SpawnCount` 已注册为 int32，原构造函数没有给 `+0x58` 赋值。为排除单一堆填充值的误判，另执行两次真实原工厂：分配区分别填充 `0xa5` 和 `0x5a`，对该字段设置 CPU 写入监测。两次该字均保留相应填充，构造期间写入次数为零。

未初始化字段证据（本地材料） 不把填充字节当成游戏默认值，也不计入 C++ 检查总数。

宿主用可选值表示该状态；属性读取实际写入后才标记为已定义。缺少属性保留已有定义值，重新创建对象则回到未定义状态。原 ARM 状态对照同样监测实际字段写入，只在已定义时比较数值。工具输出 `SpawnCount: null`、`SpawnCount_defined: false`，不把未知内存伪装成 0 或 -1。完整游戏中的后续初始化/订阅者行为尚未恢复。

## 独立工具与实际资源

Cowboy 输入仍为 APK 内置工具 `assets/pvz2tool/features/level_replace_enable/COWBOY_DANGERROOM.RTON` 的既有解密明文，没有删除或重编码其他声明。原 ARM 的选定类环境与源码工具均创建声明 1 的 WaveGeneratorProperties，加上开场、矿车、种子栏，共 4/5 个对象。

该资源的 Waves 列表为空，ZombiePool 有八个条目。本轮没有把空 Waves 的实际资源作为非空波次的证明：另用依据真实模式构造的聚焦样例验证事件、僵尸生成记录、全部池增删列表和循环引用。两种来源分别保存在 example 目录。

工具将引用按逻辑包名、对象名及本地目标序号输出；驻留编号与加载历史有关，不作为独立工具 JSON 的身份。原始引用位模式仍在 C++ 状态检查中逐项对照。未加载的外部 ZombieTypes/HeroTypes 目标保留符号名称和空本地目标，不会创建假对象。

默认启用十类；`--seedbank-only`、`--railcart-only`、`--intro-only` 可重现前三轮范围。所有模式的独立工具检查通过。真实 Cowboy 部分结果返回 `3`，聚焦波次图返回 `0`；另外三份 Festival 资源仍各装载 1/6 个声明，即种子栏。

```powershell
# 在 native_recovered 中执行，实际资源部分装载，返回 3
.\build\rton_load_objects.exe ..\native_analysis\core_round28\wave_reflection\example\cowboy-dangerroom.raw.rton partial.json --wave-only
# 支持类的聚焦非空波次图，返回 0
.\build\rton_load_objects.exe ..\native_analysis\core_round28\wave_reflection\example\wave-cycle.raw.rton objects.json --wave-only
```

普通源码构建和工具运行不依赖原引擎；仅重取 ARM 证据时读取原 `libSrc.so`。明文准备仍沿用既有 Python 解密，原生资源解密未恢复。重现本轮证据可执行：
