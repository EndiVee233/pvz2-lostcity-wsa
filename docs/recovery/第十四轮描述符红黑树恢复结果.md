# 第十四轮：描述符索引写入、旋转与删除平衡

本轮已用恢复出的红黑树代码替换描述符索引中的 `HostDescriptorIndex/std::map` 后端。创建、描述符查找、对象解析、释放删除和延迟回收现在可以通过这些恢复源码连接运行，独立编译仍不读取或链接原始引擎库。完整游戏的源码构建尚未达到。

源码：[engine_slot_index.hpp](../../native_recovered/include/engine_slot_index.hpp)、[engine_slot_index.cpp](../../native_recovered/src/engine_slot_index.cpp)。类名现为 `DescriptorIndex`；调用方已同步更新。

## 恢复范围

| Ghidra 地址 | 恢复行为 |
| --- | --- |
| `011e5b08` | 三字无符号描述符 lower-bound |
| `011ecc78` | 唯一键普通插入位置与重复键判断 |
| `011ecdc8` | 提示插入位置；相邻节点快速路径及普通查找回退 |
| `011ecff0` | 分配候选节点、处理重复键、连接节点并增加计数 |
| `014e2c4c` / `014e2c7c` | 左旋与右旋，包括根和父子连接更新 |
| `014e2cac` / `014e2cf0` | 前驱与后继遍历，供提示及普通插入使用 |
| `014e2d78` | 插入后的变色与旋转平衡，维护最小/最大节点 |
| `014e2e64` | 删除移植、极值维护及黑节点删除平衡 |

共十个核心原函数；另执行并覆盖前驱包装入口 `014e2d58`，其调用被合并进 C++ 前驱辅助函数，不另计独立语义操作。地址仍采用既有 Ghidra 加载偏移 `0x10000`；描述符专用函数为 ARM，共用树函数为 Thumb。

节点采用原来的颜色约定：0 为红，1 为黑，头节点为红。头节点保存根、最小和最大节点；空树的根为空，两端指回头节点。键是三个无符号 32 位字，依次比较，不能按有符号值排序。

唯一键插入遇到重复描述符时保留旧值；上层槽位创建的 `put` 行为则会覆盖该描述符对应的句柄。两种行为分别验证，未混为一种容器操作。

删除含两个子节点的节点时，原算法把后继节点移植到原位置并交换相关颜色，再释放被删除的原节点；没有复制键值后删掉后继。恢复实现保持这一规则，因此其他存活节点的地址不因本次删除改变。

`attach` 将当前实际树连接映射到第十二轮的 `DescriptorNode` 读取接口，只补充宿主指针视图，不重新构造另一棵平衡树。节点分配、宿主指针宽度、整体析构遍历、调试检查和读取视图映射属于移植层；并未声称恢复后的对象可以直接作为原 ARM32 内存结构使用。

## 原始指令与源码对照

原 ARM/Thumb 执行 270 个多步场景，共 3,995 个操作后完整树状态检查点。只拦截成功分配的 `operator new/delete`；所有树查找、提示处理、前驱/后继、旋转、插入与删除平衡均执行原始指令。

每步完整记录头节点颜色、根/最小/最大节点、计数，以及所有节点的颜色、父/左/右连接、三字键和两字句柄。地址按键排序后转成节点序号，C++ 对全部整数逐项比较，未以哈希代替树结构比较。同时检查红黑性质、严格排序、父子连接、分配/释放成员关系、存活节点地址稳定、栈及被调用方保存寄存器。

场景包含三节点全部插入/删除排列、四节点多种排列、七节点混合次序、提示位置矩阵、高位无符号键、重复插入与覆盖、删除缺失键，以及八组固定种子的混合操作。删除覆盖红/黑叶节点、仅左子节点、仅右子节点，以及红/黑双子节点。

## 仍需继续恢复

描述符索引已不再使用宿主 `std::map` 或“读出映射后重新平衡”的替代实现。ProfileStore 自身仍使用之前的宿主档案后端，尚未迁移到这些引擎模块。

类型名称树与对象名称树的完整写入、类型注册及 RTTI、字符串驻留与回收、真实对象构造、资源加载和完整存档序列化仍未完成；更上层的战斗、渲染、动画、声音和关卡运行时也尚未具备源码构建条件。

检查限于成功分配、有效提示、稳定节点和单线程操作，未覆盖分配失败、无效迭代器/提示、重入与并发；新代码中的参数检查或异常不代表原引擎的错误处理。取证脚本需要原始 `.so`，普通源码构建和检查程序无需原库。本轮未修改 APK、安装内容或用户存档。
