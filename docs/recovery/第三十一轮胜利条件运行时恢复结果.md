# 第三十一轮：胜利条件判断与外部模块连接

本轮在第三十轮基础上继续恢复，新增实际运行时条件判断 `00b78c70` 的有界 C++ 实现，以及 ZombiesDeadWinConProperties 数据工厂。危险房间模块的字段已定位，但本轮没有将其纳入已完成恢复。

## 运行时判断

原 `ZombiesDeadWinCon` 的注册回调跳板 `00b78ee0` 尾跳至 `00b78c70`。原函数执行以下步骤：

1. 通过 `0021a1c0` 取得 Board `+0x9ec` 的对象指针列表，并复制列表。
2. 对每个对象调用 `0024eeb8(object, 2)`。该辅助函数测试对象 `+0x1c` 与掩码 2；命中时直接返回 0。
3. 枚举类型编号 `0x25` 的对象句柄；逐个复制、规范化，查询对象库并解析对象。
4. 空句柄、缺少对象库或解析不到对象时继续遍历。对有效对象调用虚表 `+0xd4`；该调用返回非零时，判断返回 0。
5. 所有检查均未阻止时返回 1，清理枚举与指针快照。

源码：[engine_win_condition.cpp](../../native_recovered/src/engine_win_condition.cpp)，接口：[engine_win_condition.hpp](../../native_recovered/include/engine_win_condition.hpp)。

这是结束条件的就绪判断，并未恢复胜利场景切换、奖励发放或完整事件总线。`0x25` 的类型业务意义、虚表 `+0xd4` 的原方法名仍未确定，源码没有把它们擅自命名成具体僵尸状态。

宿主接口提供场上状态快照、对象库访问和虚调用。原代码复制的是对象指针，再逐个读状态；宿主测试适配器直接复制状态字。当前仅验证单线程静态对象场景，未声称对象在判断期间发生改变时行为完全等价。符号句柄所有权由 copy/release 接口承接，取证仅覆盖直接/空句柄，尚未覆盖完整驻留池副作用。

## 数据工厂与真实跨包引用

实际执行原类型入口 `00b78a90`、模式注册及工厂 `00b78784`，确认 ZombiesDeadWinConProperties 继承 LevelModuleProperties，分配大小 `0x20`。模式仅有继承字段 m_thisPtr（+8）和 ResourceGroupNames（+0x10），未发现本类新增反射字段；工厂的弱引用和字符串向量字段均为空。

源码通过可选的 `register_zombiesdead_class()` 注册为第十三种具体数据类，并复用已恢复的继承字段读取。默认装载 CLI 仍保持十一类，`--sundropper` 保持十二类，避免改变前轮工具输出；第十三类通过新跨包检查程序和库 API 启用。

真实 Cowboy 与 LevelModules 两包载入后，关卡模块连接由 4 增至 6（上一轮为 5），新增加 ZombiesDeadWinCon 的外部连接。LevelModules 创建数量从上一轮 3/66 增至 4/66，其余声明仍未创建。此连接仅证明配置对象可解析，没有创建或绑定实际运行时 ZombiesDeadWinCon 游戏实例。
