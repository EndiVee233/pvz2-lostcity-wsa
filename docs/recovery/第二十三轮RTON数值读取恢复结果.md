## 本轮恢复范围

覆盖 `011f8d6c`、`011f9070`、`011f8a24` 的非引用分支，以及 `011f1288` 的宽字符串取低字节再解析十进制路径。整数定宽载荷保留原符号扩展或低 32 位规则；浮点负数转 uint32 饱和到零，转 int32 保留负值，超出范围按原辅助函数饱和，NaN 转整数为零。布尔转换不把默认值强制压成 0/1；未知标记原样返回调用方默认位模式。

原字符串布尔语义仅看首字符是否为零或字符 `0`，例如 `false` 字符串得到真。本实现保留原行为。宽字符串数值解析先按原四字节宽字符的低八位转换，未替换成 UTF-8 数字解释。

RTID 标量分支仍依赖对象解析器，宿主明确报未实现。十进制文本仅验证 signed32 范围及 C 语言环境内的规则，越界文本在宿主报范围异常。原 atoi/strtol 调用由 32 位宿主 C 运行库受控提供，不宣称 Android libc 的溢出、区域设置或 errno 完全等价。64 位整数、浮点结果读取及完整对象值反序列化仍未补齐。

因此本轮登记为三个入口的部分分支恢复，**不把它们增加为三个完整原函数**；此前 113 项语义操作统计保持不变。

## 距离纯源码 APK

本轮只读核查了现有签名 APK、原库哈希、实际编译类目录和当前原生构建。APK 仍包含 8 个与原件一致的 `.so`；85 个 Java 源文件生成 169 个类，全包为 8 个 DEX、50,457 个类；已恢复 C++ 为 Windows x64 独立模块，未生成 Android 引擎库，也没有接入 32 个 Java native 声明的 JNI 实现。当前不能完全从源码构建可运行游戏。

完整验收点、剩余阶段及统计边界见 [完全从源码编译进度](完全从源码编译进度.md)。本轮未重建、替换或安装 APK，未修改原加密资源、游戏数据和存档。
