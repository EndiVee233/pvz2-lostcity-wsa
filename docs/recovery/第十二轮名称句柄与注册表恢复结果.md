# 第十二轮：名称句柄与注册表解析链

继续以“不依赖原始引擎库，从恢复源码编译”为目标。本轮将六个引擎函数恢复成 C++17，实际编入独立静态库，并以原始 ARM 执行结果逐项核对。完整游戏源码构建尚未实现。

## 新增源码

- 接口：[engine_registry.hpp](../../native_recovered/include/engine_registry.hpp)
- 实现：[engine_registry.cpp](../../native_recovered/src/engine_registry.cpp)
- 检查：[engine_registry_tests.cpp](../../native_recovered/tests/engine_registry_tests.cpp)

| Ghidra 地址 | 恢复行为 |
| --- | --- |
| `011e7570` | 按驻留名称编号查类型树，再选择两张类型表并检查边界 |
| `011e6840` | 从有效句柄取槽位 `+0x14/+0x18/+0x1c` 的三字描述符；无效时返回全零 |
| `011e6890` | 三字描述符精确查找，核对实际槽位内容，再按索引大小重建直接句柄 |
| `011e6a90` | 对象名称编号查描述符，再调用描述符到句柄的转换 |
| `011e761c` | 普通句柄复制；名称句柄分解为类型名称与对象名称，查找并维持驻留引用顺序 |
| `001ea034` | 通过上述转换定位类型库，解析对象，必要时执行延迟回调，最后清理临时句柄 |

所有地址沿用既有 Ghidra 加载偏移 `0x10000`，原始 ELF 地址为表中地址减去该值。

## 关键行为

树比较使用无符号编号。类型名称树和对象名称树都采用 lower-bound 搜索再检查精确命中；不能将相邻名称误认为命中。描述符树按照三个 32 位字依次比较，命中后还会核对目标槽位中的三个字，内容不符返回空句柄。

从槽位重建句柄时，索引小于 `0x10000` 使用 16 位索引和 32 位代数格式；达到该值后使用 24 位索引和 24 位代数格式。本轮包含跨越此边界的原始执行与源码检查。

名称句柄解析先 retain 类型名称并读取其文本地址；找到类型库后才 retain 对象名称并读取其文本地址。对象查找完成后先 release 对象名称，再 release 类型名称。查找按驻留编号进行，这两处树函数本身不比较文本。名称句柄高字的 `0x40000000` 不进入类型名称编号。

原 `011e6890` 假定描述符树中存放的句柄可解析到有效槽位，之后直接解引用结果。恢复接口将这一点列为使用前提；宿主代码对违反前提抛出异常，这是明确标注的宿主保护，不是恢复出的原游戏错误处理。

## 实际验证

原 ARM 共执行 138 个场景，新六个函数与第十一轮的四个函数直接串联执行，没有用 Python 或回调替换内部查找逻辑。受控边界只有驻留表单例/retain/release/文本读取，以及外部延迟加载回调体。检查同时核对栈、被调用方保存寄存器和输出边界哨兵。

C++ 使用这些原始输出作为参考，138 项返回值、驻留引用/文本访问/回调顺序比较全部通过。覆盖七节点树、空树、命中/未命中、高位无符号键、描述符各字不一致、类型表越界/空项、普通句柄失效、名称句柄转换、两种句柄编码以及零/一/两个延迟回调。原始对象解析与多回调覆盖包括：首个回调填入对象后仍继续调用第二个。

通过 `native_recovered/build.ps1` 使用本地 Zig 0.13.0 实际完成 C++17 编译、归档、链接和运行，项目源码启用 `-Wall -Wextra -Werror`。结果：

```text
PASS 18 profile lifecycle checks
PASS 47 dirty-state checks
PASS 37 engine handle ARM differential checks
PASS 138 engine registry ARM differential checks
```

合计 240 项通过。静态库和四个检查程序已生成于 `native_recovered/build/`。CMake 目标已同步更新，但本轮未执行 CMake 路径。

## 当前边界与后续接入点

本轮恢复的是稳定注册表的读取与对象解析链。宿主树视图由调用方提供，尚未恢复原始红黑树的写入、平衡、注册分配和销毁；驻留表内存、资源加载和回调内部仍通过接口接入。未覆盖失效描述符索引、并发修改或回调导致存储扩容，也未将这些静态结果当作真实关卡运行的证据。

工程构建和四个程序运行不读取、加载或链接原始 `.so`；反向验证脚本需要读取原始库以执行 ARM 指令。新模块尚未接入 APK 或 ProfileStore，原 APK、已安装游戏和存档未在本轮修改。

下一步应恢复类型库/槽位的创建、分配、删除和代数更新，补齐驻留表的实际计数与回收，再以这些实现替换宿主视图的手动构造。战斗、渲染、动画、声音、关卡和资源运行时仍需继续恢复，当前不能从源码编译运行完整游戏。
