# 离线修复与源码恢复第三阶段

已解决独立测试包中持续显示的“服务器通讯中”遮罩。WSA 实测可以确认昵称、关闭公告、点击开始游戏并进入“神秘埃及－第1天”教程。另修复了独立包存档路径权限问题，冷启动后玩家资料能够保留。

当前可用安装包：独立离线 APK（本地材料）。包名为 `com.popcap.pvz2cthd.reconstruction`，与原版并存；未卸载原版、未清除其数据。

## 离线修复

原网络桥接在系统网络连接正常时向原生游戏报告联网，即使旧服务器没有响应，游戏仍可能停在通信遮罩。此次通过测试包的 Manifest 元数据 `pvz2.reconstruction.offline=true` 启用离线分支：

- `AndroidHttpProxy.GetNetworkStatus()` 返回原有“网络不可用”值 `0`。
- `AndroidHttpTransaction.run()` 在离线模式下立即调用原错误回调并结束，避免等待请求超时。
- 未配置该元数据时，保持原网络分支。离线辅助方法是此次新增功能，不冒充反编译所得的原始代码。

修复后，欢迎页不再被持续通信遮罩挡住，按钮可以操作。冷启动已有本地资料时，游戏可能弹出可交互的云存档网络故障提示，点“跳过”即可继续。这与原先没有可操作按钮的持续通信遮罩不同。没有伪造服务器登录、云存档或支付成功结果。

## 本地资料保存

原 `Resources_GetUserDataFolder()` 将路径拼接到原版应用的外部目录。独立包使用不同 UID，在 WSA Android 13 中访问该位置时确认出现 `Permission denied`，导致重启后重新创建昵称。

现在只对独立测试包返回自身私有目录下的 `files/userdata`，原版包名仍使用原逻辑。原生引擎随之将玩家资料写入 `files/userdataNo_Backup/pp.dat`。实测该文件已写出，强制结束进程并冷启动后哈希保持一致，主菜单仍显示同一昵称，没有重新进入新玩家欢迎页。

!冷启动后玩家资料仍在（本地材料）

这证明了此次本地资料读写与冷启动检查通过；未证明所有关卡、长时间存档升级或云端合并均已正确。

## Java 源码继续恢复

本轮新增 **54 个**实际参与构建的 Java 文件。目前主 DEX 中 `com.popcap` 下导出的 **84 个 Java 文件全部纳入编译**，加上启动入口共 **85 个 Java 文件生成 169 个类**。

整个 APK 的 `com.popcap` 命名空间共有 170 个类，剩余一个是原编译器生成、现已不被新代码引用的旧枚举跳转表，继续保留原 Smali。这个覆盖范围不是整个 APK 或原生游戏引擎的源码恢复比例。

新增恢复范围包含配置/XML 解析、通知数据、奖励和时间策略、服务通信 Binder 接口、网络表单工具、日志和崩溃处理、微信回调、购买适配、R 与 BuildConfig 常量。

修复的编译问题包括反编译器错乱的异常变量及重复异常分支、不可访问的常量接口引用、捕获变量名称不一致，以及原编译器生成的访问桥接名称/返回类型与 javac 不同。六个原访问桥接已显式还原，生成 Smali 中恢复其 `synthetic` 标记。未将反编译警告本身当作语义正确的证明。

旧通知方法 `Notification.setLatestEventInfo` 已从 Android 30 编译接口移除，因此新增仅供编译的 `android-30-legacy.jar` 声明。它不包含可用运行时实现，也不打入应用。实际发送通知在现代 Android 上的兼容性、支付和分享流程仍未完整验证。

## 验证后继续的原生反编译

继续追踪了 Java 网络状态到原生缓存的调用链，恢复了 32 位对象布局片段和两个原导出结果中未单独出现的小入口：

| 原始 ELF 地址 | Ghidra 地址 | 已确认作用 |
| --- | --- | --- |
| `0x0136a2b0` | `0x0137a2b0` | 获取 Java 整型网络状态，写入对象 `+0x24`；Java 接收对象位于 `+0x08` |
| `0x0136a488` | `0x0137a488` | 次级基类指针减 4，尾跳转到完整析构入口 |
| `0x0136a4b0` | `0x0137a4b0` | 次级基类指针减 4，尾跳转到删除析构入口 |

对象分配大小为 `0x34`，两个虚表指针位于 `+0x00` 与 `+0x04`。使用原 ARM 指令完成 **11 项**有界检查：5 种状态值传递、两个指针调整入口各 3 种地址；确认缓存写入位置、其他对象字节以及栈/返回地址行为。

JNI 环境和整型调用结果在仿真中由钩子提供，未把它当成完整 JNI 或游戏引擎验证。源码片段保留未知字段，尚未编译或链接为替代原库。

## 复现与当前限制

构建和离线包生成方式见 工程 README（本地材料）。通过 launch-wsa.ps1（本地材料） 的 `-App Reconstructed` 可启动已安装的离线包，入口使用用户提供的 WsaClient 路径。

离线功能由独立包 Manifest 显式开启；`output` 下保留原包名的正式重建 APK 默认仍采用原网络分支。下载或安装本页首部的独立离线 APK 才是本轮已验证结果。

已恢复的 Java 层可以修改和重新构建，但游戏 C++ 核心仍依赖原始 `.so`，其他 SDK 代码大多仍从 Smali 汇编。完整战役、实际支付、分享、系统通知和云服务未完成验证，目前不能称为完整游戏源码。
