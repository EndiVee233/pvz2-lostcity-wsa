# 第十九轮：RTON 字段编码与对象库元数据写入

新增可独立编译的 `RtonWriter`，从现有 `OwnedStore/InternPool` 生成对象库元数据字段的实际 RTON 字节。它可以连续追加多组字段、复用窄字符串缓存；本轮未添加完整文档根结构或游戏对象载荷。

## 原始依据与行为

| Ghidra 地址 | 实现范围 |
| --- | --- |
| `011e6b70` | 对象库元数据字段、顺序及条件 |
| `01200a88` | 零、无符号变长、ZigZag 和四字节整数的编码选择 |
| `01200230`、`012000d4` | 普通窄字符串、键和缓存新增/引用 |
| `011fd650`、`011fdb58` | 32 位 varint 与带逻辑长度的原始窄字符串 |
| `011fd9d4`、`011fd77c` | 宽字符数量、UTF-8 字节长度及逐字符编码 |
| `01205280` | 本轮仅覆盖 mode=0 宽字符串分支；不计为完整函数恢复 |
| `011fd5c8` | 取证执行原字节追加的调用方预分配缓冲区分支；动态扩容与计数模式未恢复 |

整数选择保留原 32 位模式：零写 `21`，短无符号值写 `24`，更短的 ZigZag 值写 `25`，其余写 `20` 和四字节小端值。测试包含有符号边界和随机高位值，不把所有数统一改成一种编码。

窄字符串保留逻辑长度和内部零字节。键使用同一个缓存：首次写 `90` 和原文，重复写 `91` 和编号；普通值使用 `81`。缓存编号按首次写入顺序生成，重复元数据写入继续复用此前编号。

宽字符串使用 `82`，先写宽字符数和编码字节数，然后写 UTF-8。原函数遇宽零字符停止；代理区值仍生成三字节，大于等于 `0x110000` 的值计入字符数但不生成字节。本实现保留这些原规则，未用系统编码器替换为另一种错误处理方式。

元数据按原顺序写入：`table_index`、`is_system_table`、有名称时的 `table_name`、非空 `display_name`、固定内容标记和 `current_package`。对象库名称跳过第一个宽字符后取低字节；当前包字段优先用包名，无包时用对象库名。系统字节在系统表上与 1 异或，普通表写零，保留原始字节结果。重复写入不改变驻留池和对象库状态。

## 验证结果

23 个原 ARM 场景、480 个逐步字节/缓存检查点全部通过。原元数据写入、整数选择、字符串红黑树查找/插入、COW 字符串、varint、UTF-8 长循环和字节拷贝实际执行，未替换为高层编码桩。受控边界为分配器、libc、单线程 kuser 比较交换及外部回调。

覆盖整数长度边界、固定种子随机数、内部零/高字节键值、超过 127 项的缓存编号、首次和重复引用、宽零字符、非 BMP、代理区及越界字符，以及 7/8/9、15/16/17、23/24/25、31/32/33、128 字符循环边界。18 个元数据场景覆盖两张类型表、默认和显式名称、显示文本内部零、原标志字节、包名设置/清除和连续输出。

每步比较输出的全部字节，以及按键排序的缓存键/编号和计数；缓存树的原指针、颜色和拓扑不是本轮等价声明。元数据写入前后还检查 owner/驻留池不变。宿主写入器用自有字节向量和逻辑缓存替代原流缓冲区、COW 和树内存 ABI。
