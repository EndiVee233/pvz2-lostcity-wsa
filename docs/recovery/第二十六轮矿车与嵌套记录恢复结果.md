## 恢复依据与规则

原工厂 `0089fd34` 创建大小为 `0x38` 的对象：继承 `GameObject` 的空 `m_thisPtr`、`LevelModuleProperties` 的空 `ResourceGroupNames`，新增空类型字符串和两个空列表。类型元数据 `008a0610`、注册入口 `008a04ac` 及字段回调 `008a0690` 确认：

| 字段 | 原偏移 | 源码装载范围 |
| --- | --- | --- |
| `m_thisPtr` | `0x08` | 已恢复的弱引用和包/别名解析 |
| `ResourceGroupNames` | `0x10` | 有序窄字符串列表 |
| `RailcartType` | `0x1c` | 窄字符串、缓存字符串，按 C 字符串在首个零字节结束 |
| `Rails` | `0x20` | `RailcartRail` 列表；每项包含 Column、RowStart、RowEnd |
| `Railcarts` | `0x2c` | `RailcartLocation` 列表；每项包含 Column、Row |

嵌套值结构由真实注册回调 `0089f928` 和 `0089faf8` 定义，各分量为 int32。原始列表扩容汇编进一步确认，新条目的所有坐标默认均为 **-1**，而非零。证据包含 `rail_resize.asm` 和 `cart_resize.asm`。

更新列表采用 resize：保留重叠范围的旧条目，再填入输入中存在的成员。输入缺少 Column 或 Row 等字段时，旧条目保留该成员；新条目则保留 -1。缩短后重新增长的条目也重新初始化为 -1。非对象元素不填字段，仍保留 resize 后的当前条目。列表容量、原指针和分配器 ABI 不属于本轮移植范围。

宿主继续以逻辑字段、类目录和对象令牌承载数据，没有复现原 Android 对象内存布局或游戏虚表。矿车类型的任意数值/宽字符串强制转换仍未恢复，遇到未支持输入会明确报错。

## 修正列表类型错误后的字段读取

首次全量对照定位到一个差异：当 `Rails` 是非数组、后面又有合法 `Railcarts` 时，原 ARM 清空了后者，最初宿主实现却读取了该列表。

原因是原 `011b7180` 的向量读取路径在类型错误后仍退出一层读取范围。`011b9bb0` 继续用进入时保存的 objdata 检查字段是否存在，但随后的属性读取已转到外层对象声明。因此，后续存在的字符串/数值字段可能得到空/零回退，后续列表也可能清空。

源码已保留本轮已验证的局部范围变化，并补充定向检查：错误 `ResourceGroupNames` 后的镜头/旁白参数回退、类型字符串回退，以及错误 `Rails` 后的 `Railcarts`。原有正常数据和前轮检查仍通过。**完整原序列化上下文栈及任意畸形输入跨对象传播尚未恢复**，未把这些有界检查扩大为通用反射读取已完成。

## 真实资源结果

输入来自 APK 内置工具资源 `assets/pvz2tool/features/level_replace_enable/COWBOY_DANGERROOM.RTON`，使用前轮保存的解密明文；来源及摘要在核对记录中。本轮没有重新编码输入或删除其他对象。

在仅注册本轮支持类的原 ARM 环境和源码装载器中，结果一致：

- 声明 2 创建 `DangerRoomLevelIntroProperties`，镜头参数为 78、468、2、2.5，旁白编号均为 -1。
- 声明 3 创建 `RailcartProperties`：类型为 `railcart_cowboy`，轨道 Column=0、RowStart=0、RowEnd=4，矿车 Column=0、Row=0。
- 声明 0、1、4 对应 `LevelDefinition`、`WaveGeneratorProperties`、`SeedBankProperties`，尚未支持。

这表示特定资源中的数据类覆盖，不是原版游戏运行结果或整游戏完成百分比。原 ARM 取证也仅注册选定类，没有假称完整游戏注册表会找不到这些未移植类。

工具默认启用八类；使用 `--intro-only` 可重现第二十五轮七类范围。实际关卡写出部分结果并返回 `3`；JSON 的 `success` 延续原装载遍历的返回值，不代表完整关卡成功。两种聚焦循环引用样例和此前 GroundEffect 样例返回 `0`，图均与保存的原 ARM 结果一致。
