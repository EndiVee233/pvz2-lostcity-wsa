## 编译修复与接口保留

修复了反编译器扩大的私有成员访问权限、非静态内部类中无法直接表达的断言字段、Base64 解码器中重复的不可达 `break`，以及购买辅助代码中错乱的 `JSONException` 变量和处理分支。两个异常处理入口在原 Smali 中汇入同一处理段，恢复后的 Java 合并为同一个异常处理块；购买验证逻辑仍保留。

少量反编译导入引用了包外不可访问的常量接口，已按原常量值替换为字符串字面量。为匹配匿名类编号，调整了购买驱动中方法声明的排列，字段初始化的相对顺序保持不变。

D8 显式使用 `--force-passthrough-assertions`，避免默认关闭断言改变恢复逻辑；生成后恢复两个显式表示的断言字段的 `synthetic` 标记。

对 84 个生成类逐项比较：原方法和字段声明全部保留，父类和实现接口一致，**30 个 native 方法声明保留**。新编译器仅新增 **6 个私有枚举辅助方法**。主 DEX 的方法 ID 数量由 16,698 变为 16,704，新增方法引用集合恰好是这 6 项，没有删除原方法引用；字段 ID 数量保持 7,678。

声明相符不是全部行为等价的证明，因此另做了下述行为检查和设备启动验证。

## 编译依赖与默认包辅助类

新增 `tools/original-dex-api.jar`，从输入 APK 的原始 DEX 提取类、字段、方法、泛型签名、异常及内部类声明。它包含 50,457 个原类声明及一个编译别名，所有非 native 方法体均为占位异常；**只供 javac/D8 识别接口，不参与 APK 打包，也不算恢复出的实现源码**。运行时继续使用原 SDK 的真实类。

输入 APK 中有命名包直接调用默认包 `DreamRootPath` 的指令，Java 语法不能直接表达。构建时使用同签名的命名包别名，随后仅将生成指令中的类描述符映射回 `LDreamRootPath;`。原实现仍在原 DEX 对应类中，未替换为占位实现。

原 APK 主活动还在 `catch(Throwable)` 内引用了两个原支持库并未定义的权限辅助方法。声明库仅补充其编译声明，保留原调用和异常行为，没有向运行时注入新实现。旧 `src/compile_only` 手写声明已不再被当前构建使用。

编译与打包会核对生成类集合，拒绝未登记的类；声明库、编译别名和测试代码均未打入应用。生成工具位于 `scripts/build_dex_reference_jar.py`，来源哈希见 声明库记录（本地材料）。

## 行为对照

使用同一套检查程序，在 WSA Android 13 中分别装载：

1. 从输入 APK 提取并核对哈希的原始 `classes.dex`；
2. 已安装的 v4 重建测试包中的 DEX。

每次 **358 项检查通过**，原始 DEX 与重建 DEX 的结果一致。两边各重复运行一次，结果保持一致。

| 内容 | 覆盖范围 |
| --- | --- |
| Base64 | 279 项检查，包含标准向量、二进制往返、URL 字母表、无填充及错误输入 |
| 输入事件 | 13 项检查，核对触摸、缩放、甩动、返回事件的固定小端字节向量和缓冲区溢出处理 |
| HTTP | 本机回环服务器上的 GET、POST、404、数据回调中取消、读取超时，共 5 种情形；检查请求与响应数据、状态、回调顺序和原生指针转发 |

HTTP 原生回调在独立测试子类中记录，不调用真实 C++ 网络对象；这能检查 Java 的回调和取消行为，不能证明 C++ 网络对象全部正确。测试子类和测试程序不在应用包中。

WSA 的 `app_process` 在两个请求模式下均报告断言关闭，记录保留实际状态；桌面 JVM 另外在断言开启、关闭时各运行 358 项检查，全部通过。桌面测试使用仅供测试的 Android 日志适配器，WSA 对照使用系统真实日志类。

WSA 中原有安装包的整包哈希与本次输入 APK 不同，因此最终对照未以该安装包作为代码基准，而是直接传入输入 APK 的原始主 DEX，哈希为 `78b7201e922f341ff8d7abe8d25e8e7552f47b2828249a0bc4d9a288f43608e3`。

## WSA 游戏启动

按用户提供的入口调用已安装的 `WsaClient.exe /launch wsa://com.popcap.pvz2cthd` 后，确认原有 PvZ 应用进程实际运行，并显示公告和网络/云存档故障提示。

v4 重建包使用独立包名 `com.popcap.pvz2cthd.reconstruction`，也通过相同 WsaClient 入口启动。已核对设备上安装 APK 的哈希与本地 v4 文件一致，主活动进入欢迎界面；截至最终采集时，日志未发现致命 Java 异常、原生致命信号、JNI 方法缺失或类校验错误。

## 构建成果与范围

8 个 DEX 的 **50,457 个类描述符保持一致**。1,726 个非 DEX 条目与输入 APK 的哈希一致，包含全部 8 个原生库和资源。签名 v1/v2/v3 与对齐检查通过，输入 APK 哈希不变。

当前高级语言恢复覆盖启动和 Android 框架部分，50,457 个类中绝大多数仍以 Smali 构建。游戏 C++ 核心继续复用原 `.so`；现有函数伪代码尚未形成可从源码编译的原生引擎。因此本轮结果应称为“可编译框架源码扩大并通过局部行为对照”，不能称为完整游戏源码。
