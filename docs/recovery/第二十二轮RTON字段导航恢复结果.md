## 已确认的行为

查询名称先查全局窄字符串表。若全局表不存在该名称，不定位对象，也不改变当前位置。若名称在全局存在但不属于当前对象，会扫描对象并停在终止标记之后。存在重复字段时返回第一个匹配项。

匹配比较的是规范化文档里的文本偏移，而非在每个字段重新比较字符串。即使扫描代码能够跳过宽键，此查询入口仍只查窄字符串表；源码未加入自动宽窄转换来改变原匹配结果。普通文本键和缓存引用键均已对照，包括宽/窄同名键和逻辑内部零。

返回字段的同时，原函数可能停在键长度或引用偏移之后，尚未读取值。各函数的位置副作用不同：类型判定只定位不推进；字段到值定位会越过键数据和链接字；数组越界下标返回零但仍推进到数组头之后。空偏移通常提前返回并保留位置，键文本指针入口则仍会从偏移零读一个字节。源码按各自行为实现，没有统一成一套默认定位规则。

原函数返回的 ARM 地址在宿主接口中表示为文档字节偏移。窄字符串视图仍以首个零字节结束；它与上轮规范化时保留完整逻辑长度的字符串表用途不同。宽键文本返回同样的字节偏移，调用方须知道原宽字符布局。

## 实际对照

22 份文档各在原外部缓冲区、内部向量两种模式下运行，共 44 个场景。每个操作核对返回值、精确读取位置和根偏移，并确认导航不修改文档字节。受控的 seek 步骤只用于准备位置，不计入 19,396 个原函数检查点。

覆盖空对象、空/多元素数组、128 元素遍历、40/65 层嵌套、重复键和缓存声明、宽/窄同名、内部零、全局不存在的名称、只存在于其他对象的名称、空偏移、错误类型、越界及高位无符号下标，以及固定种子的混合随机文档。原指针按文档基址规范化为偏移后比较。

十四个检查程序已在 PowerShell/Zig 0.13.0、C++17、`-Wall -Wextra -Werror` 下完成构建、归档、链接和运行，全部通过。新增输出：

## 独立工具与真实资源

`rton_inspect.exe` 将关卡明文转换为内部格式，再通过新导航接口读根字段、`objects` 数量、每个对象的 `objclass` 与 `aliases`。摘要中的类型只是声明文本，没有执行反射对象构造。

| 资源明文 | 对象声明数 | 与原 ARM 摘要 |
| --- | ---: | --- |
| COWBOY_DANGERROOM，enable | 5 | 完全一致 |
| FESTIVAL_LV3_HARD，disable | 6 | 完全一致 |
| FESTIVAL_LV3_HARD，enable | 6 | 完全一致 |
| FESTIVAL_LV3_NORMAL，disable | 6 | 完全一致 |

总计 23 个声明，包含 `LevelDefinition`、`WaveGeneratorProperties`、`RailcartProperties`、`SeedBankProperties` 等类型。工具生成的根字段偏移、值标记、对象顺序、类名和别名均与原 ARM 导航生成的 JSON 完全一致，未重复计入累计检查数。详见 工具对照记录（本地材料）。

在 `native_recovered` 内使用：

```powershell
.\build\rton_inspect.exe input.raw.rton summary.json
```

工具只处理明文，摘要视图要求窄根键及窄字符串声明；它不是完整 JSON 导出器。资源明文沿用上轮既有 Python 准备流程，未将解密计为本轮恢复，也未改写原加密资源。

重新取证为 `scripts/recover_rton_reader.py`，参考数据导出为 `scripts/export_rton_reader_fixtures.py`。文档规范化和导航均由原指令执行，不使用查找/遍历测试桩。

## 剩余边界

宿主读取器拥有文档、逻辑字符串表和独立位置；未复现原 ARM 指针/COW/树内存 ABI、多视图共享流位置、并发或分配失败。越界输入、坏链接或循环链接不在等价验证范围，宿主越界访问抛出异常。上轮未知/不符数组数量的字节转换对照，不等于已确认这些输出可以安全导航。

通用标量类型转换、完整值读取、反射类注册/对象创建、对象数据填充和引用解析、资源运行时、原生解密及 Android 接入仍未完成，整个游戏还不能完全由源码生成可运行 APK。原 APK、安装内容和存档未修改。
