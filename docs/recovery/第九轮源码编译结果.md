# 第九轮：原生恢复模块首次独立编译运行

本轮已将上一轮的档案管理 C++ 片段做成实际可编译工程，而不只是伪代码或汇编补丁。

- 工程：[native_recovered](../../native_recovered/README.md)
- 构建入口：[build.ps1](../../native_recovered/build.ps1)
- 静态库：`native_recovered/build/pvz2_profiles.lib`
- 可执行检查程序：profile_tests.exe（本地材料）

本机使用官方发布的便携 Zig 0.13.0 C++ 工具链，下载包 SHA-256 与官方索引一致。使用 C++17，项目源码启用 `-Wall -Wextra -Werror`；实际完成目标文件编译、静态归档、可执行文件链接和运行，结果为 `PASS 18 profile lifecycle checks`。工具链首次构建自身 libunwind 时有导出声明属性警告，最终退出码为 0；没有将这些依赖警告当作源码错误隐藏。

工程包含五项恢复出的操作及新写的内存后端。检查覆盖中文名称、切换与失败时保持选择、改名后同步请求顺序、过滤命中位置、删除后首档回退、失效句柄、删除最后一个档案及空集合回退。内存后端用于让已恢复逻辑独立运行，未声称它就是原游戏注册表或文件保存代码。

## 距离完整游戏编译的边界

| 部分 | 当前状态 |
| --- | --- |
| 启动入口和主 DEX 的 com.popcap Java | 85 个维护源文件已有既往编译验证 |
| 档案管理原生语义模块 | 本轮完成独立编译、链接和运行 |
| 其他第三方 Java 代码 | 仍主要依靠 Smali |
| 原生对象注册表、引用计数、RTTI | 仅部分恢复，独立模块使用宿主后端 |
| pp.dat 加密序列化及备份写盘 | 仍依赖原引擎；已有分析工具可读取，未恢复成此 C++ 库 |
| 植物、僵尸、战斗、动画、渲染、声音、资源运行时 | 仍依赖原始原生库 |
| 整个游戏由恢复源码生成 APK | 尚未达到 |

本轮没有修改已安装的 v5 APK。独立模块不需要原游戏 `.so` 就能编译，但它本身不具备运行游戏的能力。后续应优先恢复对象注册表和 PlayerInfo 序列化接口，才能逐步减少宿主替代实现，并最终接回 Android 引擎。

构建记录：[build-validation.json](../../native_recovered/build-validation.json)。工具链下载依据为 [Zig 官方下载索引](https://ziglang.org/download/index.json)，本地完整校验信息保存在工具链目录的 `download-provenance.json`。
