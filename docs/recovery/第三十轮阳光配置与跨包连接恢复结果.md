# 第三十轮：阳光配置与真实跨包引用

本轮先核对本地现状，确认已有第二十九轮的对象注册表、RTON 数据链、十一类具体数据工厂及 Cowboy 五对象连接，而非当前对话较早记录中的第十一轮。随后恢复 SunDropperProperties 的工厂和五个浮点属性，并实际连接来自外部 LevelModules 的阳光配置。

## 新恢复内容

原类型入口 `00959cd0`、工厂 `009597c8` 及真实模式注册执行后确认该类继承 LevelModuleProperties。对象分配大小为 `0x30`，继承字段为 m_thisPtr 和 ResourceGroupNames。五个直接字段如下：

| 字段 | 原偏移 | 原工厂默认值 |
| --- | --- | --- |
| InitialSunDropDelay | 0x1c | 0 |
| SunCountdownBase | 0x20 | 0 |
| SunCountdownRange | 0x24 | 0 |
| SunCountdownMax | 0x28 | 0 |
| SunCountdownIncreasePerSun | 0x2c | 0 |

原内存顺序中 Max 在 IncreasePerSun 之前，不能按实际资源字段排列猜测偏移。源码采用五个 IEEE float32 位模式，复用已恢复的读取器；缺少属性时保留旧值，未知字段忽略。

真实反射管理器、工厂、RTON 规范化、两遍对象装载及字段分派实际执行。捕获五个连续数据状态：工厂默认、真实 LevelModules 中五项值对应的聚焦输入、部分更新、负零、未知字段；C++ 逐字段对照 25 个位模式一致。此项只核对五个直接字段，不宣称完整对象库/驻留池状态、析构或所有数值强制转换已新增覆盖。底层分配/C 库和空事件总线仍沿用先前受控边界。

## 真实跨包场景

独立检查程序按顺序加载以下未删减的资源明文：

1. 既有 Cowboy DangerRoom：CurrentLevel 包的五个对象，模块引用解析 4 条。
2. 原 `game_data/packages/dynamic.rsb.smf/PACKAGES/LEVELMODULES.RTON` 解密明文：注册为 LevelModules 包，源码创建 3/66 个声明对象。

加载第二包后，原关卡的 DefaultSunDropper 引用解析为 SunDropperProperties，模块连接数从 4 增至 5。五项实际参数的 float32 位模式与原资源数值一致：2、4.25、2.75、9.5、0.1（按内存顺序）。其余未支持声明仍保留空对象，没有创建替代对象。跨包检查属于源码集成检查，并未把完整两包图在原 ARM 中再次逐状态对照；原 ARM 差分只覆盖上文五个数据状态。

未恢复阳光生成、掉落计时、随机范围、模块实例化或关卡更新。当前仍不能运行关卡，也未接入 Android/替换 libSrc.so。
