## 恢复依据

| Ghidra 地址 | 行为 |
| --- | --- |
| `011f83b0` | 从外部缓冲区或内部向量读字节，推进位置 |
| `011f83f0`、`011f8440` | 32/64 位变长整数 |
| `011f84b4`、`011f84d0` | 32/64 位 ZigZag 解码 |
| `011f8508`、`011f8554` | 带逻辑长度的窄字符串、原始四字节宽字符串 |
| `011f85a0`、`011f8624` | 字符解码与按字符数读取宽字符串 |

| `011f873c` | 内部 RTON 头校验及根偏移设置 |

所有十一个入口都执行原始指令，没有将读取器或字符解码器替换为高层测试桩。分配器、libc 和原字符串所需的单线程 kuser 比较交换由受控环境提供，原 COW 字符串操作仍执行。

## 确认的细节

变长整数按原 ARM 寄存器移位规则处理：移位量取低八位，大于等于 32 时该次 32 位移位结果为零。64 位结果按原低/高字组合。超长但终止的输入也保留原行为，未改成宿主语言可能出现的未定义移位或统一拒绝。返回有符号结果的位模式，避免宿主有符号溢出。

窄字符串保留内部零和高字节；原始宽字符串按四字节小端值读取，保留逻辑零和任意 32 位值。UTF-8 字符串先读字符数和声明字节数，但原实现不按声明字节数决定解码边界，而是按输入剩余长度解码指定次数。

字符解码器与现代严格 UTF-8 库的接受范围不同：接受部分超出 `0x10ffff` 的四/五字节序列，拒绝六字节序列、过长编码、代理区及 `0xfffe/0xffff`。解码失败不改变调用方输出值，也不推进输入；字符串读取包装层会在该位置反复得到零字符。ASCII 零字符则消费一个字节。这些差异均保留并纳入对照。

内部头检查每次先回到位置零，读 `RTON`、版本 1、内部格式 1，成功才更新根偏移。原始资源使用的格式 0 不由此函数直接接受。原流程还需 `01202a74/012028a0` 等转换与索引构建；本轮没有把“能读基础类型”宣称为“已能加载完整资源”。

## 验证

466 个原 ARM 场景，2,140 个返回值和状态检查点全部与 C++ 一致。每步比较全部字节/宽字符/整数、读取位置、根偏移与头状态，并检查原输入未被修改。覆盖外部缓冲区和内部向量两种原存储模式；宿主接口统一采用自有字节缓冲区，不复现原内存 ABI。

覆盖 32/64 位边界及固定种子随机值，2 至 150 字节的超长终止整数，全一、尾部单比特和混合载荷；后两类用于实际检验跨越移位宽度及低八位回绕的行为。字符测试覆盖全部 256 种首字节、合法边界、每个续字节处的截断/非法值、五字节序列、禁止值和失败重复读取。字符串测试包括内部零、声明字节数不符，以及多种长度循环边界。头检查包含错误签名、版本、格式和重复调用。

另有六个双存储模式场景：由原第十九轮写入函数生成输入，再由原读取函数读取；C++ 先用 `RtonWriter` 复现输入的全部字节，再用 `RtonInput` 对照原读取结果。它们覆盖 varint、含零和高字节的窄字符串、中文和非 BMP 宽字符串。

## 剩余边界

原裸字节读取要求调用方保证范围；宿主接口对越界读/定位抛出 `std::out_of_range`，不宣称该错误处理与原无检查内存访问等价。ARM 裸读取场景满足原范围前提；非法 UTF-8 测试使用原函数已有的长度检查。未覆盖分配失败、并发或任意超大分配。

原始到内部 RTON 的转换、缓存及索引构建、字段导航、反射对象创建、完整对象数据、资源文件 I/O 和 Android 接入仍未恢复。本轮不修改原 APK、安装内容或存档。
